# Participation in STALKER X CCZMP

The project is open to **voluntary cooperation** of developers, animators, 3D artists, testers and technical authors.

**Participation does not constitute employment. There is no guaranteed pay, no promises of income, no hours quota, or commitment to complete tasks.** Amount of assistance is determined by each participant; refusing an offer is normal.

## How to respond

1. Create a GitHub Issue with the title **[Volunteer] Direction - nickname** (or reply to an existing recruitment thread).
2. Specify a convenient public method of feedback and language of communication. **Do not post your personal number, home address or private credentials.**
3. Attach links to your portfolio: public repository, video, demo, ModDB/ArtStation or screenshots.
4. Write what tasks are interesting: Lua/Anomaly 1.5.1, X-Ray SDK, 3D OGF/OMF, CCar, NPC AI, animations, QA, documentation.
5. After the initial selection, we will agree on a **small voluntary and limited in scope** technical analysis/demonstration. We do not require a large free test task.

## Rights to code and assets

- Indicate authorship, source and licenses; Do not send third-party work without permission.
- Availability of sources and their successful conversion does not mean permission to distribute.
- We discuss the rights to contributions and terms of use before integration. No automatic alienation of rights based on one fact of communication.
- For materials with an unclear license, use a clean example/description rather than a closed model or archive.

## Technical discipline

- Indicate the exact version of the game/engine and dependencies (currently Anomaly 1.5.1).
- Attach reproduction steps, expected/actual behavior, anonymized logs.
- Show separate unit/mocked and native game checks.
- Do not create public issues with personal data, tokens, private gamedata and complete other people’s assets.
- Corrections to a private build are made only with agreed access, license checks and backups.

See [actual status](docs/STATUS_EN.md), [technical overview](docs/TECHNICAL_EN.md), [roadmap](docs/ROADMAP_EN.md).


## Documentation changes

Start with [documentation index](docs/INDEX.md). Indicate the date, implementation version and source of verification. After changing the status, synchronize the current roster, overview and roadmap; save historical reports. Rebuild the catalog and check the links according to [instructions](docs/INDEXING_EN.md). For a game test, specify native or mock and a specific script separately.
