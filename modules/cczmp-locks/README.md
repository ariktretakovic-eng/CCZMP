# CCZMP Locks — исходный модуль и проверяемый тестовый стенд

**Проект:** [STALKER X CCZMP](../../README.md) · **База:** S.T.A.L.K.E.R. Anomaly 1.5.1 / X-Ray · **Снимок исходников:** 09.10.2026 · **Контрольная проверка:** 29.10.2026

> **Статус: рабочий интегрированный прототип / source showcase.** Это реальный Lua-код CCZMP и минимальная подборка его зависимостей, а не псевдокод и не автономный установщик. В тестовом окружении пройдены **21/21 профильных регрессионных проверок** (LuaJIT 2.1 через Python/Lupa). Отдельные игровые проверки с холодной загрузкой подтверждены сохранёнными отчётами 09.10.2026, но **полный нативный прогон на текущем составе игры 29.10 не проводился**.

## Что реализовано

- **PIN 4–8 цифр**, включая начальные нули; три неправильные попытки включают блокировку на 300 игровых секунд.
- Временный доступ **120 игровых секунд**. После загрузки сохранения открытый доступ не восстанавливается автоматически.
- До **12 небольших предметов / 10 кг** содержимого; кейс учитывает массу груза.
- Вещи перемещаются как **оригинальные объекты ALife**, не как созданные заново копии.
- Контроль идентичности по UID/ID/имени/секции, фиксация **pending-трансферов**, защита от повторного извлечения и повторных действий.
- Сохранение состояния предмета и восстановление прочности после загрузки там, где нативная сериализация не удерживает её.
- Игровая «кодовая отмычка» с потреблением заряда, требованиями к навыкам, игровым временем выполнения и сохраняемой задачей.
- Интерфейс инвентаря/кейса интегрирован в оболочку CCZMP, но не вынесен в отдельное независимое приложение.

**Важно:** это логика *вымышленного игрового* кейса, а не криптографический сейф. PIN хранится в игровых данных; авторизация рассчитана на игровые механики, не на защиту настоящих секретов.

## Архитектура и исходники

| Путь | Назначение |
|---|---|
| [`cczmp_locks.script`](gamedata/scripts/cczmp_locks.script) | PIN, доступ, контейнер, перенос, восстановление и блокировка |
| [`cczmp_items.script`](gamedata/scripts/cczmp_items.script) | Реестр предметов, UID, токены, состояние, задачи |

В папке `gamedata/` оставлены **15 связанных авторских Lua-модулей** и **8 конфигураций** — ровно тот программный набор, на котором запускается приложенный стенд. Другие подсистемы включены только как зависимости стенда; **не** заявляются частью самостоятельного выпуска Locks. В `tools/` находятся четыре Python-файла тестового окружения.

## Как запустить проверки

Требуется Python с установленным [Lupa](https://pypi.org/project/lupa/) (сборка с `lupa.luajit21`). Из **этой папки** выполнить:

```powershell
python -m pip install lupa
python -m unittest discover -s tools/items_work_20261009 -p test_locks.py -v
```

Ожидаемый результат: `Ran 21 tests ... OK`. Тесты используют эмуляцию доступных Lua/X-Ray API и **не запускают саму Anomaly**. При подготовке публичной версии из тестового импорта убрана запись в `test_items.py`: стенд повторно пройден, и SHA-256 тестового файла не изменился во время запуска. [Протокол проверки](TEST_REPORT.md).

## Интеграция в игру

**Не копируйте целиком этот каталог поверх вашей `gamedata`.** Он не содержит ассетов, полного регистратора конфигураций, всех рабочих пользовательских экранов и совместимого манифеста для произвольной сборки Anomaly. Для игры необходим базовый мод CCZMP с его инициализацией, предметами, UI и ресурсами. Исходники здесь нужны для аудита, тестирования и демонстрации инженерной реализации. [Интерфейсы и ограничения](INTEGRATION.md).

## Что ещё не проверено

- Перемещение кейса/контейнера между всеми игровыми локациями нативным тестом;
- удаление или разрушение контейнера во всех состояниях и сложные сценарии потери предметов;
- регрессионная проверка после всех последующих изменений сборки 10–28 октября;
- длинные игровые прохождения, баланс цен, пользовательские 3D-анимации и готовый сетевой режим.
